## 1. 拆分层已经引入的回归 / 明确 bug

### 1.1 中文字体丢失（高优先级，UI 会大面积空白）
`src/GameFont.cpp:10` 只加载 `fonts/arial.ttf`；Arial 没有中文字形，而 UI 里全是中文
（`飞船 / 资源 / 视野模式 / 击杀 / 称号…`）。
0.1.4 在 `GameFont` 里有 5 级回退：霞鹜文楷 → 微软雅黑 → 思源黑体 → 得意黑 → Arial，
最后还回退到 `C:/Windows/Fonts/msyh.ttc`（`ver0.1.4.cpp:218-236`）。
**改法**：直接恢复这份候选列表；字体路径改用 exe 所在目录解析（见 §5.3）。

### 1.2 初始飞船从 20 艘变成 40 艘
`src/Game.cpp:104` 用 `rows = {4,3,2,1}`，每阵营 10 艘 × 4 = 40 艘；
0.1.4 是每阵营 5 艘 = 20 艘。密度、碰撞数、AI 扫描量全部翻倍。
如果是为「舰队感」有意改的，建议保留但在 HUD 显示总数；否则先回到 20 艘做基线。

### 1.3 说明书键位与代码不一致
`沙盘说明书.txt:6` 写「P 关闭/开启叛乱系统」，代码是 `O`（`src/Game.cpp:238`）。
同时 `Tab`（视野模式）、`L`、`H`、鼠标点击都没写进说明书。

### 1.4 引力小行星是死代码
`AsteroidType::GRAVITY`、`applyGravity`、`gravityRadius/gravityStrength` 都在，
但 0.1.4 的生成分支是 `roll < 1000` 之后才轮到 GRAVITY（永远到不了，注释写「0.0% 暂时关闭」），
拆分层则直接删掉了这个分支（`src/Game.cpp:188-197`）。
**要么补完生成与平衡，要么把类型和相关代码删掉**，别留半套。

### 1.5 UI 布局重叠 / 错位
- 底部左侧阵营面板：位置 `(20, 900-100=800)`、高 80 → 占 800–880；
  底部状态栏文字在 `900-40=860` → **重叠 20px**（`src/UISystem.cpp:144-149` 与各 `drawXxxInfo`）。
- 「历史」开关：文字在 `y=860`，背景在 `y=760` → **背景高了 100px**（`src/UISystem.cpp:353-366`）。
- 四块阵营面板固定按窗口四角摆，1600×900 下不挡，但缩放/改分辨率会错位；建议用布局常量集中管理。

### 1.6 窗口被创建了两次
`src/Game.cpp:7` 初始化列表创建一次，`:14` 又 `window.create()` 一次。功能上能跑，但多余且可能引起上下文/闪烁问题。
**改法**：初始化列表只写 `window()`，在函数体里 create 一次。

### 1.7 激光存了两份、0.1.4 里画了两遍
每艘船 `lasers` 存一份，`PhysicsSystem::lasers` 再存一份；
`Spaceship::draw` 画本地列表（`src/Spaceship.cpp:614`），0.1.4 的 `PhysicsSystem::draw` 又画全局列表 → 同一条激光画两次。
拆分层目前 `PhysicsSystem::draw` 只画 objects，暂时没重复，但**补物理绘制时不要再加一遍**。
更彻底：激光只保留在 `PhysicsSystem`，`Spaceship` 只记引用/不做绘制。

### 1.8 历史窗口重置按钮首帧点不中
按钮命中区用的是 `getGlobalBounds()`，而它只在 `drawHistoryWindow` 里设置尺寸；
首帧未绘制前 bounds 为 0，且点击判定在选船之后（`src/UISystem.cpp:115-117`）。
属于小问题，改布局时一起处理。

## 2. 性能：按收益排序（先加测量，再改）

### 2.1 碰撞检测是最大热点
`checkPixelCollision` 对每一对候选调用两次 `getPixelBlocks()`：
- `Asteroid::getPixelBlocks()` **每次 new 一个 vector 并过滤活跃像素**（0.1.4:1866-1874）；
- 然后像素对像素双重循环，O(n×m)。半径 80 的小行星约 1300 像素，两两就是 ~170 万次 AABB/contains。
- `getBoundingRadius()` 每次遍历全部像素（0.1.4:1964-1975），在碰撞、激光、绘制里被反复调用。

建议：
1. `getPixelBlocks()` 返回 `const std::vector<...>&`，不再拷贝；
2. 缓存 `boundingRadius`、`activePixelCount`、`convexHull`，像素变化时更新；
3. 粗判用「包围圆 + SAT/凸包」，像素级只做最后确认；碎片可直接用小圆近似；
4. 同一帧内对同一对物体只算一次（已有 pair 去重，但去重本身是 O(k²)）；
5. 极端情况限制每帧处理的碰撞对数或分帧。

### 2.2 小行星顶点每帧全量重建
`src/Asteroid.cpp:92` 每帧 `verticesDirty = true`，`draw` 时重建所有四边形顶点。
位置/旋转变化其实可以用 `sf::Transform` 表达：
- 顶点数组只在像素变化时生成一次（局部坐标）；
- 绘制时 `window.draw(vertices, sf::RenderStates().transform)`。
这样每帧只是提交一次 draw call，不再写几万个顶点。

### 2.3 `getType()` 返回 `std::string`，热路径全是字符串比较
`obj->getType() == "Spaceship"` 出现在碰撞、绘制、AI、清理的每个循环里。
建议改成 `enum class ObjectType { Ship, Asteroid, LightPoint }` 或 `const char*`；
用虚函数返回枚举，扩散最小。

### 2.4 AI 每帧全表拷贝
`Spaceship::scanForObstacles`（`:307`）、`findEnemyInView`（`:799`）、`findAsteroidInView`（`:821`）
都调用 `getObjectsInWindow()`，而它**每次新建 vector 并复制 shared_ptr**。
40 艘船 × 10Hz 扫描 → 每秒几百次全表拷贝。
建议：
- 每帧由 `PhysicsSystem` 生成一次 `frameSnapshot`（窗口内对象、按阵营分组）；
- 或给空间网格加 `queryRadius(pos, r)`，AI 不再遍历全表；
- 返回 `const&`/复用成员 buffer，避免每帧分配。

### 2.5 光点系统是隐藏的 O(S×L)
`processLightPointCollection` 每帧对每艘船调用 `collectNearbyLightPoints()`，
后者遍历**全部光点**；`findLightPointInView` 也是全表。光点会被小行星掉落的 5% 概率不断制造，
长时间运行后数量可能上千，绘制还是每个光点两个 `CircleShape`（两次 draw call）。
建议：光点也用网格分桶；收集判定只查 3×3 网格；绘制合并为 `sf::VertexArray`/点精灵。

### 2.6 可变步长 + 半隐式欧拉
`Game::update` 直接拿 `dt` 更新物理，碰撞和 AI 行为随帧率变化；
高速彗星 300–400 px/s、像素 4px，帧间穿透风险高。
建议：固定步长 `1/60` 累加器（最多补 5 步），渲染可选插值；至少把物理与帧率解耦。

### 2.7 其它可顺手做的
- `getConvexHull()` 返回值拷贝，改为 `const&`；
- HUD 文本每帧重建 `sf::Text`（等级数字、历史窗口）→ 缓存字符串/布局；
- 抗锯齿 8 对大量小图形偏贵，可试 4 或关闭，对比观感；
- 加 FPS / 帧耗时 / 对象数 / 光点数 overlay，先量化再优化（现在完全没有测量手段）。

## 3. 物理与逻辑正确性（补实现时一起修）

1. **友军碰撞伤害**：`resolveCollision` 没有阵营过滤，同阵营飞船互撞也扣血。若不想内耗，加 `factionId` 判断。
2. **装甲被结算两次**：0.1.4 里 `damage` 先被 A 的装甲削减，再被 B 的装甲削减，最后 A、B 都吃这个最终值（`ver0.1.4.cpp:2950-2990`）。应各自独立计算。
3. **没有位置修正**：碰撞只改速度、不推开重叠物体 → 持续多帧重叠、连续扣血。加穿透深度修正 + 伤害冷却（小行星有 0.5s，飞船没有）。
4. **高速穿透**：彗星的扫掠检测缺失，建议用线段/扫掠圆或子步。
5. **`getObjectsInWindow` 只按中心点判断**：大 asteroid 一半在屏内也「看不见」；改成半径与窗口相交。
6. **引力实现**：`applyGravity` 每帧 `getAllObjects()` 拷贝全表，且对光点也施力（光点 update 不读 acceleration，纯浪费）。启用前重写。
7. **随机数混用**：`rand()` 与 `std::mt19937` 并存；建议统一 mt19937，并在窗口标题/日志显示 seed，方便复现。
8. **拖尾双重更新**：0.1.4 里 `Spaceship::update` 调用 `updateKillTrail`，`PhysicsSystem::update` 又调一次（`ver0.1.4.cpp:3620`）→ 粒子速度/寿命双倍推进。补实现时只保留一处。
9. **区域时长硬编码**：`UpgradeZone::update` 用 4/12/4 秒三段，但 `maxLifetime` 是 16s；改常量后会变成负半径。用比例计算。

## 4. 玩法与表现（沙盘方向）

### 4.1 最值得加的「观察工具」
- **空格暂停 / 1、2、4 倍速 / 单步**：沙盘没有暂停很难看清一次交战。
- **FPS、实体数、光点数、每阵营资源 overlay**：既是调试也是观赏信息。
- **选中飞船后镜头跟随/高亮**：现在点击只弹属性面板，船 5px，很容易跟丢。

### 4.2 可读性
- 40 艘 5px 三角 + 拖尾 + 激光，只靠颜色分阵营，色弱/小屏很难分辨；
  加**形状差异**（三角/菱形/方形/箭头）或更明显的描边，比单纯加亮更有效。
- 加血条弧/等级点、击杀数徽章；称号触发时来一条「击杀播报」。
- 选中判定半径 8px 偏小，建议按 `boundingRadius` 或 12px 判定，并加悬停高亮。

### 4.3 反馈与氛围
- 命中闪光、爆炸粒子、屏幕轻震、彗星掠过时的拖影；
- 音效可以**程序生成 wav**（正弦/噪声包络），不必找素材，SFML 直接加载；
- 背景加极淡的星点/星云，黑底目前略空。

### 4.4 世界与镜头
当前「窗口边缘 = 墙」是设计前提（说明书 + `isOutOfBounds` + 边界避障），
世界 2400×1700 只用于生成小行星。加自由镜头会破坏这个前提。
折中：加一个**全图俯瞰模式**（`sf::View` 缩放，只读），同时把 AI 的 `isInWindowView` 改成「战场边界」语义；
或者维持现状，只做「奇点方向指示器」，让玩家知道场外在发生什么。

### 4.5 持久化与终局
- 视野模式、H/L/O 开关、窗口位置写入 `config.ini`，启动读取；
- 历史系统已有击杀/损失/新造数据，可加「本局统计」面板（运行时长、总击杀、阵营胜率）；
- 沙盘没有胜负没关系，但需要一个「我看了 5 分钟发生了什么」的总结。

## 5. 工程与流程（结合 AI工具箱）

### 5.1 工具箱现状
`AI工具箱\config.ps1` 整份还是 Snrs 的路径：
`Exe/WorkDir/ShotDir/ProjectRoot/Solution/BuildOut` 全指向 `H:\C\Snrs`，`TitleHint='Snrs'`。
要用在本项目，至少改：

```powershell
Exe         = 'H:\C\Darkfield Lightwar\dist\Darkfield Lightwar.exe'
WorkDir     = 'H:\C\Darkfield Lightwar\dist'
TitleHint   = '暗域光战'
WindowClass = 'SFML_Window'
ShotDir     = 'H:\C\Darkfield Lightwar\tmp\shots'
ButtonColor = <从截图取样>       # 目前 UI 没有按钮，probe 主要用不上
ProjectRoot = 'H:\C\Darkfield Lightwar'
Solution    = 'H:\C\Darkfield Lightwar\Darkfield Lightwar.sln'
BuildOut    = 'H:\C\Darkfield Lightwar\x64\Release\Darkfield Lightwar.exe'
```

它的三条纪律（一个进程多次操作、客户区坐标、改代码才重启）对后续验证依然完全适用。
但注意：**现在没有 exe，`session.ps1 start` 无意义，必须先构建成功**。

### 5.2 建议补的工具
- `build.ps1 -Deploy`：构建后把 exe + 10 个 SFML DLL + `fonts/` + `names/` 拷到 `dist/`，并校验哈希；
- `--headless N` 模式：不开窗口跑 N 秒模拟，用于回归/性能测试（现在没有任何自动化测试）；
- `shot` 前 park 鼠标（工具箱已有），但本项目主界面没有按钮，park 点选左上角空白即可。

### 5.3 资源路径
`fonts/arial.ttf`、`names/*.txt` 都是相对工作目录。
从 VS 启动、双击 exe、快捷方式的工作目录可能不同 → 字体/名字加载失败。
建议启动时用 `GetModuleFileName` 求 exe 目录，拼绝对路径；或统一 `--data-dir` 参数。

### 5.4 版本管理
现在只有 `versions/` 手工快照。建议 `git init` + 每次改动前 commit，
`versions/` 保留为里程碑（0.1.4 就是很好的基线），避免「一次改五处，坏了不知道是谁」。
